# OpenCV 流水线模式 UI 设计

## 目标

在不改动现有 `index.html` 单步实验行为的前提下，为离线项目增加可直接双击运行的 `pipeline.html` 流水线入口。用户可以组合多个 OpenCV 步骤、修改每步参数、查看所有中间结果并导出等价 JavaScript 代码。

## 范围

首版支持灰度化、高斯模糊、二值化、Canny、形态学和轮廓检测；支持添加、删除、启停、上移、下移、参数编辑、三个预设、自动运行、中间预览、最终结果下载、流水线 JSON 导入导出以及 JavaScript 代码复制。

不在首版范围内：自由连线 DAG、分支/合流、视频流、Python/C++ 完整代码生成、模型推理和云端保存。

## 架构

- `pipeline-mode.js`：与 UI、OpenCV 具体算法解耦的有序步骤引擎。通过注册表取得默认参数、显示名称和处理函数；负责步骤状态、序列化、执行顺序与矩阵生命周期。
- `pipeline-operations.js`：OpenCV 注册表、六种处理器、默认参数和三个预设。
- `pipeline-editor.js`：节点列表、参数控件、预设应用与代码生成。
- `pipeline-app.js`：页面状态、图片加载、运行调度、中间预览、导入导出和错误提示。
- `pipeline.html` / `pipeline.css` / `pipeline-stage.css`：离线结构、构建器样式、画布与编辑器响应式样式，按固定顺序引用同目录资源。
- `tests/`：使用 Node 内置测试框架验证引擎行为和页面关键结构，不引入第三方依赖。

## 数据流

1. 图片绘制到 `sourceCanvas`。
2. `cv.imread(sourceCanvas)` 创建输入矩阵。
3. `OpenCVPipeline.run()` 按顺序执行启用的步骤。
4. 每步输出克隆一份用于预览，上一工作矩阵及时释放。
5. 最终矩阵绘制到 `resultCanvas`，历史矩阵绘制到动态预览画布。
6. 新一轮执行前调用执行结果的 `dispose()`，保证 WebAssembly 内存可回收。

## 错误处理

- OpenCV 加载失败时禁用运行相关操作并展示明确提示。
- 未加载图片、流水线为空、参数非法或处理函数抛错时不破坏上一张原图。
- 引擎在执行异常时释放所有已拥有矩阵，再将原异常抛给 UI。
- JSON 导入校验版本、步骤类型和参数对象；未知步骤拒绝加载。

## 兼容性与离线约束

- 不使用网络请求、CDN、框架或构建步骤。
- 继续使用项目内嵌的 `opencv.js` 4.6.0。
- 桌面 Chrome、Edge、Firefox 为主要目标；窄屏采用单列布局。
- `index.html` 继续作为单步实验入口，`pipeline.html` 作为流水线入口。

## 验收标准

- 双击 `pipeline.html` 后可加载内置示例并运行预设。
- 六种步骤均可加入流水线并编辑核心参数。
- 调整顺序、禁用或删除步骤后结果重新计算。
- 每个启用步骤产生独立中间预览，最终结果可下载。
- 导出的 JSON 可再次导入并还原流水线。
- `npm test` 与 `npm run check` 全部通过。
